How to require permissions on the HTTP API

RequirePermissions has every route of the HTTP API check the host's policy named for its permission: read, enqueue, control, or admin. A caller with no credential gets 401, and one that lacks the permission gets 403 naming it.

Remember

  • The name in [Job("sample-task")] and the namespace in Run<HttpApiAuthorizationJobs>("http-api-authorization") are stored with every job. Treat both as permanent once jobs exist under them: a job stored under a name no handler carries stays Ready, and nothing runs it.
  • SampleTask is stored with each job as its input. Add a field as optional or with a default. A renamed, removed or retyped field needs a new job name such as sample-task-v2, and the old handler stays registered until its jobs have finished: Change a job's input without breaking the jobs already stored.
Notes on the program

RequirePermissions = true makes Acta authorize every route of its HTTP API, reads included, against the host's policy named for the route's permission: acta.read, acta.enqueue, acta.control, or acta.admin, the constants of ActaPermissions. The host defines the four policies with AddAuthorization, each requiring a claim here. The host also owns authentication, and Acta ships none, so the program defines a header scheme of its own that believes the permission a caller names, which only a demo may do.

The run calls the API in-process as callers holding one permission each and prints what the server answered:

  • With no credential, GET /acta/api/v1/jobs answers 401.
  • acta.read reads the jobs list (200) and is refused pausing a job (403, whose detail names acta.control).
  • acta.enqueue enqueues a job (201) and is refused pausing it (403).
  • acta.control pauses it (200) and is refused purging it and suspending the namespace (403, naming acta.admin).
  • acta.admin suspends and resumes the namespace (200).

Each operation names the permission it needs as x-acta-permission in the OpenAPI document.

Run the experiment

It runs on the local SQLite database, like every how-to, and exits when the calls are done.

Break it

Delete the acta.admin policy and run again: mapping throws, naming the missing policy, before the host serves a request. Put it back and add options.ConfigureEndpoints = group => group.AllowAnonymous(); to the mapping: every call answers as before, because Acta evaluates the policies in its own endpoint filter, which an AllowAnonymous on the routes does not switch off.

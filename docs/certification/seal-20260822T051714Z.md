**Verdict: PASS** — the fourth gate of the `1.0.0-rc.1` round and the one with the widest shape:
**three participants, two namespaces**, one run id, one seal. `namespace-isolation` is falsifiable
here and nowhere else in the round — a second namespace was live, executing, and being killed beside
the first — and it held. This run also carries the release candidate's non-vacuous `AtMostOnce`
evidence: 47 charges interrupted mid-body, zero bodies ever run twice.

## Namespace isolation, falsifiable and held again

`cert-b` was not an empty row: it registered 76 workers, ran its recurring system slots plus Anvil's
pulse, recorded its own execution events (26 of them, beside `cert-a`'s 14,038), and had 60 of its
workers reclaimed dead, all while every participant killed workers every five seconds. The check
compares each execution event's namespace against its owning job's across the whole schema: **zero
rows**. No worker in either namespace ever emitted an event for work it did not own, under contention
that included a second live namespace to get wrong.

The three participants behaved as the shape requires, which is itself part of the evidence. `p2`
joined the seeder's run thirty seconds after it started, claimed from the same queue for the whole
chaos window, and exited cleanly with code 0 once the run's work went terminal, having correctly
declined to render a verdict it does not own. `p3` holds no seeded workload — only `cert-b`'s five
recurring slots — so it has nothing to quiesce on and was stopped after the seeder's verdict.

## The double-spend claim, non-vacuous this time

The three single-participant runs of this round all reported `at-most-once = 0` with zero interrupted
charges — vacuously true. Here the kills landed: of 400 charges, **47 were interrupted mid-body** and
terminalized as ambiguous rather than re-run, 353 succeeded, and every one of the 400 wrote exactly
one witness note — **no charge body ever ran twice** (maximum bodies per job: 1; jobs with two or
more bodies: 0). That is the contract stated exactly: zero or one executions, never two, with an
honest "this may have happened once" instead of a confident second charge.

## Scope

Single machine, three processes; the participants are process-isolated, not network-isolated.
`cert-b` carried recurring work rather than a second seeded workload — enough to make isolation
falsifiable, not a throughput claim for two namespaces at once. Only a namespace's seeder stages
outbox rows, so `cert-b`'s relay drained an empty, pre-provisioned producer file and the outbox
evidence in this seal belongs to `cert-a`. The checks are `anvil/Anvil/certify.sql` with the schema
token bound to `certrc1ens`.

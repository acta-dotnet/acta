# Acta certification seal

**Verdict: PASS** — the `1.0.0-rc.2` ensemble run, fourth and final gate of the round. Three
participant processes, two namespaces, one shared run id, on PostgreSQL. This is the only gate where
`namespace-isolation` can actually fail and the only one that interrupts charges mid-body, which is
what makes the at-most-once claim non-vacuous rather than a property asserted against a workload that
never tests it.

**The 29 Failed rows are the point of this gate, not a blemish on it.** This is the only run that
interrupts charges mid-body, so a job whose retry budget is spent while its charge is in flight lands
terminal Failed by design. `expected-outcome` compares every terminal status against what the
workload declared it should be and returned 0, so all 29 are inside the declared envelope. A run of
this shape with zero failures would mean the interruption never landed.

## Scope

Two namespaces, three participants, one machine, one PostgreSQL schema. Checks are
`anvil/Anvil/certify.sql` bound to `certrc2oens`; re-run them against that schema to reproduce the
verdict. `at-most-once` and `namespace-isolation` are the two properties this gate exists to make
falsifiable — both read 0, against a workload that gave them every chance to fail. Throughput is not
measured here.

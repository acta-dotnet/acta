## Why this round exists

The release candidate's own review quorum found a defect no gate had been looking for: PostgreSQL
evaluates an identity default before it detects an `ON CONFLICT`, so `start_worker`'s namespace upsert
allocated a `namespaces.id` on **every worker start**, whether or not the namespace already existed.
SQLite had the same defect for the same reason. Ids are never reclaimed, so the 16-bit space counted
every namespace ever created and the burn drained it at worker-restart rate.

The fix gives both providers the shape SQL Server always had — update first, then an insert whose
SELECT produces no row, and therefore calls the allocator no times, when the name is already present.
The widening of `namespaces.id` from smallint to int followed, because a public, additive-only surface
cannot widen after 1.0. Both stamp constants moved to `baseline-1.0.1`: every M001 statement is
existence-guarded and the preflight verifies history rather than schema, so an amended M001 under an
unchanged stamp would let a smallint database boot green and fail later on a conversion.

A seal certifies a commit, and that work re-cut the baseline. All four gates therefore re-run from
empty schemas at the same shapes, and the previous round's seals are superseded.

## The burn, measured under chaos

Chaos respawns a killed worker every five seconds and every worker start calls `start_worker`, so this
gate makes 81 registration calls against a single namespace. The previous round's schema is still on
the same server and serves as the control:

| | Previous round | This run |
|---|---|---|
| Worker starts (`start_worker` calls) | 80 | 81 |
| Namespace rows / highest id | 2 / 2 | 2 / 2 |
| **Allocator position after the run** | **81** | **2** |
| **Ids burned** | **79** | **0** |
| Holes between lowest and highest id | 0 | 0 |

One id burned per respawn, then none. `namespaces.id` reads as `integer` in
`information_schema.columns`, so the widening is in the provisioned schema and not merely in the
migration file.

**Stated plainly:** zero charges were interrupted mid-body this run, so `at-most-once = 0` is vacuous

charges wrote exactly one witness note and none wrote two. The non-vacuous version of that claim is
this round's ensemble seal, which interrupted 43.

## Scope

One namespace, one machine, one participant. The schema holds two namespace rows — the reserved `sys`
row, which owns no jobs, and the run's own — so `namespace-isolation` runs schema-wide and passes but
cannot fail; the 3-participant / 2-namespace ensemble seal covers that. The checks are
`anvil/Anvil/certify.sql` with the schema token bound to `certrc1bpg`; re-run them against that schema
to reproduce the verdict.

# Acta certification seal

**Verdict: PASS (reduced scope)** — 10,000 jobs, all eight checks green, produced by
`anvil --role certify` rather than by reading queries by hand.

| | |
|---|---|

| Provider | PostgreSQL 18.4 |
| Schema | `acta_cert3` |
| Workload | Anvil `CrashRecovery`, **10,000 jobs**, 8 worker processes × 8 executors = **64 concurrent slots**, 5 durable steps each |
| Chaos | Real `Process.Kill` every 5s throughout the run |
| Quiesce | Chaos stopped, then waited for `runtimes` to hold nothing in `Dispatched`/`Executing` |

**Timing — framework production defaults, unmodified**: `LeaseTtlSeconds` 180, `HeartbeatInterval`
45s, `WorkerDeadAfter` 5min, `SafetyPollInterval` 1s. Every property below is timing-dependent, so a
run with different values certifies that configuration, not the shipped one.

**834 step bodies re-ran, against 984 orphaned attempts** — each killed worker re-ran at most the one
body in flight when it died, and the shortfall is the orphans killed between steps rather than inside
one. **Zero bodies ran after their step had already succeeded** (check 7). That is the product's
central claim, at 10× the scale of the previous seal, and every one of the 10,000 jobs still landed
`Succeeded`.

## Scope — what this does NOT say

- **Not "lease exclusivity"** — check 1 is execution-event ownership consistency, which is narrower.
- **No handler-body overlap, no `AtMostOnce()` double-spend** — both need witnesses that do not exist.
- **Single host, single namespace, no tenants, no outbox. One provider.**

## Reproducing

```bash
dotnet run --project anvil/Anvil -- --provider pg --schema acta_cert3
# POST /anvil/api/run  {"workload":"CrashRecovery","load":10000,"workerCount":8}
# POST /anvil/api/faults/crashes/start
# ... run well past the ~4 minute lease floor ...
# POST /anvil/api/faults/crashes/stop, then wait for in-flight to reach zero
dotnet run --project anvil/Anvil -- --role certify --provider pg --schema acta_cert3
```

The last line is new: it runs `certify.sql` and prints the verdict, exiting 0 on PASS, 1 on FAIL,
2 on INCONCLUSIVE. Reading the checks by hand is what produced every wrong call while building this,
and the two non-PASS outcomes now carry the guidance that was missing.

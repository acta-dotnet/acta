## What this gate settled

**`no-stranded-work` is the check that matters here.** The reclaim sweep runs only from the
`sys.recovery` slot, and a slot is an ordinary job a worker can die holding, so a kill that lands on
it stops the sweep that would have freed it; on a pre-fix tree that left 573 rows in flight for good.
Every worker now checks that one slot, at startup and once an hour, with a single guarded statement
that re-arms it only when its lease has lapsed. Same workload, same kill rate, same slot count:
15,000 of 15,000 terminal, nothing stranded, and 573 orphaned attempts reclaimed on the way.

**The re-cut type carries its column under kills.** `job_schedule_advance_batch` gained
`expected_version` in this cut of `M001`, and every recurring completion in this run passed it through
`complete_execution`; a binding or a routine that disagreed about the type's shape would have failed
the first recurring fire. `at-most-once` and `terminal-integrity` read 0, so the locking changes of
the previous round, `FORCESEEK` on the `runtimes` updates and the heartbeat's lock order, held again
on the final tree.

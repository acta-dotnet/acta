# Acta certification seal

**Verdict: PASS** — the ensemble shape on SQL Server: two processes, one run id, one shared queue, one
seal. Provider parity for the two claims first tested on PostgreSQL the same day — `AtMostOnce` never
double-spending, and tenant context surviving every hop — on an engine with different locking,
isolation and routine dialect.

## The two new claims

**`AtMostOnce` never double-spent.** 400 charge jobs, **30 interrupted mid-body** and terminalized as
ambiguous rather than retried, and **exactly 400 bodies across 400 jobs** — never two for one job. The
30 is what makes the zero mean something: the charges are enqueued due after the warm-up and spread
across the remainder of the chaos window, so the kills land inside the bodies rather than after them.

Fewer interruptions than PostgreSQL's 50 out of the same 400, on a run with almost identical orphan
and dead-worker counts. That is scheduling luck about which attempts were mid-body when a kill landed,
not a property of the engine.

**Tenant context survived every hop.** 4,847 witness notes, each recording the `TenantKey` the handler
actually observed, compared against the tenant stored on the job row.

## The clock note reads differently here, and that is worth stating

**32 backwards writes**, against 4,747 on the PostgreSQL run of the same shape and 42,707 on the
earlier million-job run on this engine. The measure is unchanged: a higher `events.id` carrying an
earlier timestamp, counted and never asserted, because a stale stamp from a write that blocked on locks
and a clock that genuinely stepped back are indistinguishable from inside the database.

The spread across three runs is the argument for keeping it measured rather than asserted. It tracks
lock contention, not correctness — and every property this seal certifies passed in all three.

## Scope

**One namespace.** This run buys queue contention and tenant spread, not cross-namespace isolation:
`namespace-isolation` runs schema-wide and passes here, but with a single namespace in the schema it
cannot fail. The configuration covering both at once — two participants sharing a namespace plus a
third on a second namespace — is one flag away and unrun.

Single machine. Outbox delivery is not asserted by any check in this file.

The checks are `anvil/Anvil/certify.sql` with the schema token bound to this run's schema; re-run them
against `certms` to reproduce the verdict.

**Verdict: PASS** — the `1.0.0-rc.2` reduced run on SQLite, third gate of the round. SQLite installs
no routines and has no table types, so the re-cut that carries a schedule version on SQL Server's
advance batch reached it as one more field in the JSON it already sends, and the recovery-slot repair
reached it as inline SQL. The baseline stamp reached it the same way it reached the servers, as a

## Scope and what is out of it

One namespace, one machine, one database file. Checks are `anvil/Anvil/certify.sql` bound to
`certrc2nsq`.

SQLite is single-node, so this run is deliberately reduced to 48 slots and several properties the
server gates assert are out of scope here:

- **Cross-process write concurrency** is serialised by SQLite itself. The lock-ordering and
  lock-escalation work done for SQL Server has no analogue, so this gate says nothing about it
  either way.
- **Batched completion** degrades to the Direct path on inline-only providers, so the Bulk profile's
  group-commit shape is not exercised.
- **`namespace-isolation`** is asserted but cannot fail on a single-namespace run; the ensemble seal
  is where that check carries weight.

What this gate does establish is that the round's schema, completion and recovery changes hold on a
provider that receives them as inline SQL rather than as installed routines, under the same real
kills.

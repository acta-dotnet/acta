# Acta certification seal

**Verdict: PASS** — the **first SQLite seal**, closing the standing gap against releasing.md's "one
run per provider": six worker processes hammering one WAL-mode database file through real kills,
with the same shape and the same outbox-handoff certification as the PostgreSQL and SQL Server
runs sealed earlier the same night — and the ledgers converged across all three engines.

**Timing — framework production defaults, unmodified**: `HeartbeatInterval` 45s, with
`LeaseTtlSeconds` 180 and `WorkerDeadAfter` 315s derived from it at x4 and x7.

**Three engines, one ledger behaviour.** 576 orphaned attempts against PostgreSQL's 584 and SQL
Server's 574; 72 workers reclaimed dead against 73 and 72; identical job, step, and receipt totals
to the row on all three. Zero clock backsteps — the embedded engine writes with no server round
trip to block on, which is the cleanest illustration yet that the backsteps note measures lock-wait
patterns rather than correctness.

**Stated plainly:** zero charges were interrupted mid-body this run (as on both server engines
tonight), so `at-most-once = 0` is vacuous here; the non-vacuous versions are the 0.8.0 ensemble
seals and this release's ensemble run.

## Scope — reduced, and stated on its face

- **Single machine is the engine's deployment model, not a shortcut**: SQLite is embedded, so every
  worker shares the database file by construction. Kills, leases, reclaim, and multi-*process*
  claim contention are fully exercised; multi-*machine* topology claims are out of scope on this
  provider permanently, not merely untested.
- **One namespace, one participant**: `namespace-isolation` passes but cannot fail with a single
  namespace in the schema; the 3-participant / 2-namespace ensemble seal covers that (on a server
  engine — the ensemble shape presumes independent participant processes joining one database,
  which is the server providers' deployment model).
- Concurrency is 48 slots against the server engines' 64: the single write lock makes more
  executors contention rather than throughput; the run certifies the shipped SQLite guidance
  (`Direct` profile, WAL), not a server-class concurrency envelope.

The checks are `anvil/Anvil/certify.sql` with an empty schema token; re-run them against
`acta-local-cert09lite.db` to reproduce the verdict.

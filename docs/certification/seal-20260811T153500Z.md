## Scope — what this does NOT say

- **Not "lease exclusivity".** Check 1 is *execution-event ownership consistency*: no two workers
  emitted execution events for the same attempt. It cannot see a claim that died before emitting
  `job.execution-started`, nor two overlapping claims carrying different execution numbers. Real
  lease exclusivity needs a storage-boundary witness that does not exist.
- **No handler-body overlap, no step-body re-execution, no `AtMostOnce()` double-spend.** The ledger
  cannot see a handler body. These need the ledger-note API and an external kill record, neither of
  which is built.
- **Single host, single namespace, no tenants, no outbox.** Cross-namespace leakage, the
  cross-namespace handoff, tenant-context integrity, transactional-rollback and outbox delivery were
  not exercised.
- **The run was stopped early.** 7,181 of 10,000 jobs never started. That does not weaken the checks
  — they assert over what actually ran — but this is not a million-job run.
- **1 provider.** SQL Server and SQLite were not certified here.

## What running it changed

Four things in the design were wrong on paper and were corrected by this run, which is the argument
for building the instrument before the hardening it measures:

1. **"Every job reaches `Succeeded`" fails a healthy run** — a realistic workload contains shapes
   designed to fail (`always-fails`). Replaced by terminal-state completeness plus a per-shape
   outcome check.
2. **Attempt pairing cannot be asserted mid-flight.** Run live, it flags every executing attempt as
   started-but-unfinished. QUIESCE is mandatory, and that is now observed rather than argued.
3. **`Orphaned` is `ExecutionStatusCode` 230**, not 220 (220 is `Cancelled`).
4. **"Chaos was real" must key on orphaned attempts, not `worker.dead`.** Recovery reclaims on lease
   expiry; 56 orphans had accumulated while event `122` was still at zero. It reached 53 eventually,
   but keying on it would have failed a run whose chaos was demonstrably real. This also sets a floor
   on run duration — lease TTL plus recovery cadence — that has nothing to do with job count.

## Reading the chaos numbers

The counts match the same-shape PostgreSQL run exactly, and that is arithmetic, not coincidence:
the kill cadence is deterministic (one kill every 5s across the 7-minute window less warm-up = 72
kills), and each killed worker orphans its 8 executing slots, 72 × 8 = 576. Two engines with
different locking, isolation (RCSI here), and routine dialects converged on identical ledger
behavior under identical chaos, which is what provider conformance is supposed to mean.

## Scope

Same reduced scope as the PostgreSQL 10,000-job seals: single namespace, single machine, one
provider per run. The checks are `anvil/Anvil/certify.sql` with the schema token bound to this
run's schema; re-run them against the schema to reproduce the verdict.

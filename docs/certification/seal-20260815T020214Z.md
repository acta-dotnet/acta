## The outbox handoff, certified across its seam

New in this seal. The staging table lives in the producer's database — a dedicated SQLite file, a
real database boundary even against a non-SQLite ledger — which `certify.sql`, bound to the Acta
schema, cannot reach. So the check is split where the ownership is split:

- **Anvil holds the producer side**: *drained* (zero rows Pending or Claimed after quiesce;
  quarantined would not hide, it fails delivery) and *delivered* — every committed producer
  operation's job exists in the ledger, counted through the run correlation key and the
  `ingress=outbox` tag. Count equality is a bijection here because deduplication keys are unique
  per staged row and per (namespace, key) in the ledger.
- **`certify.sql` holds the ledger side**: every job the relay created ran to `Succeeded`
  (`outbox-relayed-outcome`), with the relayed count reported beside it as evidence.

The 5,000 rows were staged in small committed batches spread across the whole chaos window, so
relay claims raced worker kills the entire time: the handoff was certified under the same chaos as
the ledger, not after it.

## Scope

One namespace, one machine, one participant. `namespace-isolation` runs schema-wide and passes, but
with a single namespace it cannot fail; the 3-participant / 2-namespace ensemble seal covers that.
The checks are `anvil/Anvil/certify.sql` with the schema token bound to `cert09pg`; re-run them
against that schema to reproduce the verdict.

# Acta certification seal

**Verdict: PASS** — the first **ensemble** run: two independent Anvil processes joined to one run id,
sharing one namespace and one queue, and produced **one seal** rather than two. It is also the first
run to test two claims that were previously asserted by nobody: that an `AtMostOnce` step never
double-spends, and that a job's tenant survives every hop intact.

## The two new claims, and why they are not vacuous

**`AtMostOnce` never double-spent.** 400 charge jobs, each running its single effect inside an
`AtMostOnce` step that writes one note per body invocation. **50 of them were interrupted mid-body**
and terminalized as ambiguous rather than retrying, which is the contract. Across all 400 jobs there
were **exactly 400 bodies** — never two for one job.

The 50 is what makes the zero mean something. An earlier run of the same shape produced 400 bodies and
zero interruptions, because the charges were seeded flat and queued behind the bulk workload, draining
only after the kills had stopped. That run's check passed without having been tested. The charges are
now enqueued due after the warm-up and spread across the remainder of the chaos window, both derived
from this run's own lease and recovery cadence rather than pasted in.

**Tenant context survived every hop.** 4,776 witness notes, each recording the `TenantKey` the handler
actually observed, compared against the tenant the job row was stored with. Deliberately not a
comparison of `events.tenant_id` to `jobs.tenant_id`: those are two projections of one stored value and
would pass by construction. This is the far side of enqueue, claim, dispatch and payload decode.

Not a security claim. The tenant field is documented as not a security or isolation boundary; this
asserts the value survives intact, not that it confines anything.

## One check was narrowed before this seal, and it matters that it was

An earlier ensemble on this configuration **failed** `attempt-pairing` with one row: a recurring slot
with a start and no finish. It was not a killed worker. Two live workers claimed the same slot 16ms
apart and took different execution numbers; the later one completed, and the earlier one's completion
was refused because the version had moved. A refused operation commits nothing, so no event is written
and the superseded attempt keeps an open start forever.

Nothing was lost or repeated — the slot ran once. Asserting that every start closes demanded a
guarantee the engine does not make, so the check now asserts what it does: an attempt never starts
twice and never finishes twice. Unclosed attempts remain covered by `no-stranded-work`, which asks the
operational question of whether any job was left mid-flight.

The narrowed check was verified in both directions: green against this run's real data, and red within
seconds of a duplicate start being injected into `events`.

## Scope

**One namespace.** This run buys queue contention and tenant spread, not cross-namespace isolation:
`namespace-isolation` runs schema-wide and passes here, but with a single namespace in the schema it
cannot fail. A separate two-namespace run (`certens2`, same day) exercised that check with two live
namespaces and passed, but predates the shared run id and so produced two seals rather than one. The
configuration that covers both at once — two participants sharing a namespace plus a third on a second
namespace — is one flag away and unrun.

Single machine. Outbox delivery is not asserted by any check in this file.

The checks are `anvil/Anvil/certify.sql` with the schema token bound to this run's schema; re-run them
against `certd5` to reproduce the verdict.
